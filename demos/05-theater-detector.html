Four of ten trees could never agree with themselves.

The depth experiment split ten root questions into sub-questions and asked whether the sub-answers agreed with the root. Three trees came back inconsistent in all four runs and a fourth in both sonnet runs, whichever model read them. That was not the models. Three of those trees end in a yes/no under a root that wants a list or a name, and the fourth never asks the step that produces the root. Code can see that from the gold answers alone, before any model is asked. This demo runs that check first, as Path 0, and sends only the survivors to the judge.

The intersection. wiring-and-the-whole built an interview to catch model defects and caught its own harness instead. jev-tape says code computes what code can compute. A composition witness is code, so it runs before the judge, and its RED is one the judge cannot override.

Check a tree

Pick a tree. COMPOSE is code: it compares the answer type of the last sub-question with the root, then checks that the last sub is the step that produces the root. Only a tree that passes goes to the judge, with one closed question: did the recorded sub-answers agree with the root, yes or no.

What the tape shows

COMPOSE is a witness, so it is code. It reads gold strings and asks two things: is the last sub-answer the same kind of answer as the root, and is it the root. Neither needs a judge, so the tape records a code cell and posts nothing. When the witness fails, that is a local RED. The judge is never asked, and a Choice from the judge could not have overridden it.

A tree that passes goes to the judge with one closed question, consistent: yes or no. The twin answers from the E5.1 grades: on the six valid trees, every run was consistent and correct. The recorded judge, asked the same question about the default tree Q43, also said yes, but at P=0.68 with a confidence field of 0.36, where the twin says yes at 0.94. Code keeps that: 0.68 clears the top_prob_floor of 0.6, so the gate is GREEN, and the reasons list shows the margin. "Run all ten" walks every tree, then sends the six survivors in a single request. That request was never recorded, so the twin answers it and the pill says so. One POST, six answers, recorded once.

The four rejected trees show what the raw run recorded instead. The three depth-9 trees were inconsistent in all four runs; the depth-10 tree in both sonnet runs. An inconsistency that does not depend on the model is a defect in the tree, not in the reader. That is how the harness caught itself, and it is a check that costs nothing.

Counterpoint

Consistency is not correctness. A model can agree with itself and be wrong; E5 saw consistent-and-wrong pairs in both directions. The OC gate calibrates and localises defects. It is never ground truth, and the 6/6 here is measured on six trees of one corpus, written by the same author as the packs.
The judge answers shown are recorded or twinned; this page never calls the judge. When the pill at the top is green, the consistency answer is the one a real call returned once, on the default state (tree Q43), replayed from data/recorded.js.
