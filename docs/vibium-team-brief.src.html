How one step runs

Two questions, one tape, four rails

The loop wraps vibium --json. Reads and tab edits never involve Jev. A commit verb pays one gate call before it runs; a step with an expectation pays one verify call after the page settles. Jev's "not sure" goes to a person for the gate and to the model for the verify.

Classify

Verb classes in code

map, text, url and fill never call Jev. Only click, press Enter and upload reach the gate. A login costs two calls, not five.

Gate

May this run now?

One call with the snapshot and the target: mutatesWorld, reversible, spendsOrSends, blastRadius. Peaked answers apply or refuse; mid-band answers escalate to policy or a person.

Verify

Did the page do it?

One call after wait load: outcome, errorShown, blocked. Entropy above 0.6 escalates to vibium check with the same claim.

Tape

Answers replay for free

Every answer is keyed by a hash of state and questions. A replayed flow makes zero calls. The recording zip is the proof and the calibration input.

Where this is the wrong tool. An unfamiliar page with no step list still needs the model to plan. A claim that is not literal about one page ("is this a good deal") escalates every time. A site that renders nothing to text (canvas apps, image-only pages) gives Jev nothing to read; the screenshot judge wins there.

The questions Jev is asked

Every question is about one page

Anything that needs comparing, counting or remembering is computed in code and handed over as a value. Text is verbatim from the packs in packs/.

before an action runs · gate
mutatesWorld
yes/no
Would this action change anything beyond the browser tab, such as submitting data, changing a record, sending a message, paying, or deleting?
yes the target submits, saves, sends, pays, deletes, or changes something the page describes as stored or sent · no it only navigates, opens, expands, filters, or reveals within the tab
reversible
yes/no
If this action turns out to be wrong, does the page offer a way to undo it without losing anything?
yes an undo, cancel, edit, or draft path is shown, or the action only opens or navigates · no the page describes it as final, or no undo path is visible
spendsOrSends
yes/no
Does this action spend money or send data to a party outside this page?
yes the target or surrounding text is about paying, ordering, sending, sharing, or publishing · no nothing is paid, sent, shared, or published
blastRadius
scale 0 to 3
How much is affected if this action does the wrong thing?
0 only what is on screen · 1 one record or form on this site · 2 a shared resource others depend on · 3 money, a message that leaves, or data that cannot be pulled back
1  spendsOrSends = yes AND reversible = no          → refuse
2  mutatesWorld = no                                → run it
3  mutatesWorld = yes AND spendsOrSends = no
   AND reversible = yes                             → run it
   otherwise                                        → escalate
after the page settles · verify
outcome
one of three
Which of these does the page evidence say about the claim?
verified the text, title, address, or newly present elements state what the claim says · contradicted the page states the opposite, or shows the state the claim says has ended · unsupported neither
errorShown
yes/no
Does the page show an error or failure message about what was just attempted?
blocked
one of six
Which stop, if any, is the page showing instead of the expected result?
one-time code · captcha · cookie banner · login wall · error page · none
login-verify
4 questions
signedInSignsShown · loginFormGone · credentialErrorShown · interstitial

0  outcome answer is spread out, not peaked        → escalate
1  errorShown = yes                                → failed
2  blocked by a code prompt, captcha,
   login wall, or error page                       → escalate
3  outcome = contradicted                          → failed
4  outcome = verified AND errorShown = no          → confirmed
   otherwise                                       → escalate

A yes/no answer counts only when Jev is confident: yes at 0.85 or above, no at 0.15 or below. Rules run in order and the first that clearly applies wins; a rule that depends on an unsure answer is skipped, never assumed. Rule 0 on verify came from the Wikipedia row in the explorer: "verified" at 0.48 with the rest spread out, and the earlier rules accepted it.

II

Observed: same page, same claim, three judges

Eight public pages, one claim each, six true and two false. Every judge saw the same settled page. Jev read the page text and element map; the model ran its tool loop; the screenshot proxy read one frame, blind.

Corpus, E9

73 of 73 decided right

80 rows, 40 pages with a true and a false claim each, three Vibium sessions in parallel, 88 s. Six rows stopped in code (a bot check, a 429 under load) before any Jev call. One escalated by the entropy rule. The lab verdict on outcome: JEV-SAFE, 98.6% against a 50% baseline, McNemar p = 2.9e-11, Brier 0.006.

Real sites, E7

The GitHub row to remember

The scripted fill never took in GitHub's search box. Jev's verify said contradicted at 0.64 in 320 ms and was right. The model-only run typed its own way and passed the page it had typed itself. A typed verify catches silent failures the model loop does not see.

What we ask of the Vibium team. Review bridge 6: two optional hooks in the verifier loop, one before every mutating tool call expecting auto | park | refuse, one after each step expecting true | false | escalate. jev-tape provides both commands. The model keeps planning; Jev gates every action it takes, and the loop's 24-action, 3-minute budget stops burning on forks a typed judge settles. Bridge 2 is a docs-only PR that can land first.

IV

Assay: what was struck, what is still a gate

The gates below are honest: each names the measurement that would strike it.

Struck ⚖

  • ⚖ 164× per decision on eight pages, at least as accurate as the model on this sample. E5.
  • ⚖ 98.6% on 74 corpus rows against a 50% baseline, p = 2.9e-11, Brier 0.006. E9.
  • ⚖ Blind screenshot judge 7 of 8 in 2.8 s; its miss was the Cloudflare wall where the image shows no npm page. E11. The first launch was not blind and is kept for comparison only.
  • ⚖ Loop shape: at most two calls per applied step, zero on replay, twin-tested against a fake binary. src/vibium/vibium.test.ts.
  • ⚖ A gate escalate handed to the model times out at 180 s with no verdict. E6-C. Model fallback is verify-only.

Gates ⊘

  • ⊘ Accuracy out of sample. Claims were written with the pages known, thresholds hand-set, no fit/test split. Struck by: the 140-row, 18-kind catalog with blind claims and a hash split, then npm run calibrate against Haiku labels.
  • ⊘ Claude computer use itself. A Sonnet proxy stood in. Struck by: the same eight pages and login from the desktop app, same blind protocol.
  • ⊘ errorShown and blocked at scale. NO-INFORMATION on the corpus because every page was normal. Struck by: the error, login-wall and consent rows already in catalog-100.json.
  • ⊘ Routine commits on auto. The gate escalated on the login submit both times and a person composed. Struck by: an operator policy for allowlisted hosts, measured on the action rows.
