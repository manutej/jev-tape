# Plan: public-facing docs across the Jev repos, with a clear path for the Vibium team

Status: planned 2026-09-29, not started. Branch for the work: `claude/docs-jev-repos` on each repo
(jev-tape, JEV-works, jev-elder), one PR per repo. This plan is the brief for whoever picks it up.

## The problem, as found on 2026-09-29

- The READMEs do not say what jev-tape and JEV-works each are, or how they differ. jev-tape's README
  opens with key handling; JEV-works' opens with the lab's philosophy. Neither draws the picture.
- `AGENTS.md` and `llms.txt` mention the Vibium surface in one line each (jev-tape) or not at all
  (JEV-works has no `AGENTS.md`; its `llms.txt` never says "browser"). A Vibium engineer, or an agent,
  cannot find the browser work from the front door.
- The good material exists but sits three clicks down: `HANDOFF.md`, `docs/HANDOFF-VIBIUM-TEAM.md`,
  `docs/vibium-team-brief.html`, `docs/TEST-IN-PLACE.md`, JEV-works `handoffs/vibium-browser.md`.
- jev-elder, the map repo, does not list jev-tape, JEV-works or the Vibium surface.

## What "done" looks like

1. A Vibium engineer lands on any of the three READMEs and reaches, in under five minutes: what this
   repo is, what its siblings are, the browser work, how to run it on their machine.
2. A conceptual diagram in each README, rendered by GitHub itself (committed SVG under `docs/diagrams/`),
   legible on light and dark GitHub themes, no private brand assets.
3. `AGENTS.md` and `llms.txt` in jev-tape and JEV-works carry one block titled "Vibium surface" that
   lists every related path, command and rule; jev-elder's `LINKS.md` and `DIGEST.md` point at it.
4. Public-facing: no keys, no internal hostnames, no brand sigils in the repos (the chrome's tokens and
   CSS are fine); the Ormus chrome pages stay under `docs/` as the presentation layer.
5. A link checker passes over every Markdown file touched (`scripts/check-links.mjs`, to write).

## Per repo

### jev-tape (the runtime)

- `README.md`: rewrite the top. One paragraph: jev-tape is the runtime that puts Jev, a typed decision
  model, in front of a browser (Vibium) and a mailbox; code classifies, Jev answers two questions per
  step, a tape replays. Then the three-repo diagram. Then "Surfaces" with the browser surface first and
  a "For the Vibium team" box: `HANDOFF.md`, the brief, `TEST-IN-PLACE.md`, `VIBIUM-BRIDGES.md`. Key
  handling moves below, unchanged.
- `AGENTS.md`: a "Vibium surface" table (paths, commands, rails) above the general rules; keep the
  existing results and presentation rules.
- `llms.txt`: a "Vibium surface" block with the full path list; keep the read-first order but put
  `HANDOFF.md` second.
- `docs/diagrams/`: `three-repos.svg` (elder = map, works = lab, tape = runtime; questions down, states
  up, results to the registry), `one-step.svg` (the lane diagram, extracted from the brief),
  `browser-layer.svg` (the four seams, extracted from the brief). Generated by `scripts/build-diagrams.mjs`
  from the brief's sources so they never drift; colors from the chrome tokens on a transparent ground
  with a stroke that reads on white and on GitHub dark.
- `HANDOFF.md`: keep; add the diagrams.

### JEV-works (the lab)

- `README.md`: after the opening, a "How this relates to jev-tape" section with `three-repos.svg`:
  JEV-works writes and lints the questions and grades the answers; jev-tape runs them against a browser;
  results flow back as items and into the registry. Then "Browser surface" with the file tree already in
  `handoffs/vibium-browser.md` and a link to jev-tape's brief.
- `AGENTS.md`: create. Read order, the nine rules in one line each with a pointer, the Vibium surface
  block, the rails (never edit `kit/results` after a run).
- `llms.txt`: add the Vibium surface block.

### jev-elder (the map)

- `LINKS.md` and `DIGEST.md`: locators for jev-tape, JEV-works and the Vibium surface (branch, entry
  file, the brief's published copy).
- `README.md`: one row per sibling in "Source of record" for jev-tape and JEV-works, marked as
  runtime and lab.

## Order of work

1. `scripts/build-diagrams.mjs` and the three SVGs in jev-tape (they are reused by the other two repos
   as copies, with a header comment naming the source).
2. jev-tape README, AGENTS.md, llms.txt.
3. JEV-works README, AGENTS.md, llms.txt.
4. jev-elder LINKS, DIGEST, README rows.
5. `scripts/check-links.mjs` run across all three; PRs opened with the diagrams in the PR body.

Estimate: one focused session. Nothing here changes code or results; the registry and the built pages
are untouched.

## Rules that bind this work

No keys, no private hostnames, no brand sigils in the repos. Every number quoted in a README comes
from `results/registry.json` totals and says so. No em dashes in visible copy. The Vibium team is the
first reader of every sentence in the browser sections; leadership is the second.
