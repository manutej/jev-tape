A typed judge in front of the browser

Jev answers the two questions a browser loop asks most, in a quarter of a second, without a model turn. Vibium does the acting. This is what was built, what was measured, and what we propose to change in Vibium.

Executive summary

On literal browser decisions, Jev is 164× faster than the model loop and was wrong zero times in 79 decided verdicts. The rest escalate to the model or a person by design.

Per decision
248ms

Median Jev answer on eight real pages. The same claim through vibium check took 41.0 s.

Wrong verdicts
0of 79

Bench 6 of 6 and corpus 73 of 73 decided right. Three escalated instead of guessing.

Whole login
5.0s

Gate plus verify with Jev, against 32.8 s for the model-only loop on the same fixture site.

Cost per call
<0.1¢

All lab runs on 2026-09-28 together cost about two tenths of a cent. No GPU, no tool loop.

The pattern: code classifies each Vibium verb, Jev answers one gate question before a commit verb (may this click run?) and one verify question after the page settles (did the page do what the step said?), a tape replays answers it has seen, and anything that touches money, sending, or deletion parks for a person before any call is made. The model stays in the loop for planning unknown pages and for the claims Jev escalates.

How it works

Two questions, one tape, four rails

The loop wraps vibium --json. Nothing inside Vibium knows Jev exists yet.

Classify

Verb classes in code

Reads (map, text, url) and tab edits (fill) never call Jev. Only commit verbs (click, press Enter, upload) reach the gate. A full login costs two calls, not five.

Gate

May this run now?

One call with the page snapshot and the target: mutatesWorld, reversible, spendsOrSends, blastRadius. Peaked answers apply or refuse; mid-band answers escalate to policy or a person.

Verify

Did the page do it?

One call after wait load: outcome (verified, contradicted, unsupported), errorShown, blocked. Entropy above 0.6 escalates to vibium check with the same claim.

Tape

Answers replay for free

Every answer is keyed by a hash of state and questions. A replayed flow makes zero calls. The recording zip from record stop is the proof and the calibration input.

The rails do not move: Jev never counts, compares, or decides a retry (code does); a Jev refusal is final; pay, send, and delete targets park for a person before any call; and no threshold moves because a result disappointed. Fallback order is Jev, then the model for verify only, then a person.

What we ask of the Vibium team. Review bridge 6: two optional hooks in the verifier loop, one before every mutating tool call expecting auto | park | refuse, one after each step expecting true | false | escalate. jev-tape provides both commands. The model keeps planning; Jev gates every action it takes, and the loop's 24-action, 3-minute budget stops burning on forks a typed judge settles. Bridge 2 is a docs-only PR that can land first.

Claims

What this shows, and what it does not

Shown

  • On literal claims about a settled page, a typed judge over text is one to two orders of magnitude faster than any model in the loop, and at least as accurate on this sample.
  • The loop shape holds: at most two calls per applied step, zero on replay, twin-tested against a fake binary.
  • Every relational judgement in a browser step has a named code replacement; Jev only answers what is visible on one page.
  • A typed verify caught a silently failed action on GitHub in 332 ms. Both model runs on that page passed it.

Not shown

  • Accuracy beyond in-sample claims: the claims were written with the pages known, thresholds are hand-set, and there is no fit/test split. The corpus of 140 rows across 18 file kinds is built and not yet run at scale.
  • Anything about Claude computer use as a product. The proxy had no desktop and one frame at a time.
  • That auto is safe for routine commits without an operator policy. The gate escalated on the login submit both times, correctly, and a person composed.
